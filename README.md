## 它是什么

投喂bot 给陪伴型 Bot 加了一条**互动玩法**：你把正在吃的东西拍给它，说一句「投喂」，它会：

1. **看懂你发的是什么** —— 视觉模型识别食物与其外观；
2. **结合人设与当前状态决定吃不吃** —— 时间、今天已经吃过几次、距上次投喂多久都会影响判断；
3. **吃了就出图** —— 生成一张「正在吃你发的这个食物」的照片。**你的照片会作为场景参考一起参与生成**，那份食物真的会被画进去；
4. **不吃就给拒绝** —— 一句符合人设的傲娇拒绝，而不是冷冰冰的「操作失败」。

一切都由**陪伴插件的人设**驱动，因此它不绑定任何特定角色 —— 换一份人格，说话方式就跟着换。

## 特性

- **自主判断，不是固定回复**：吃 / 不吃由模型结合状态决定；同一天连续投喂会被嫌「太饱了」。
- **你的照片真的参与生成**：食物图作为**场景参考**接入生图，而不是只靠文字描述「一碗红油面」。
- **保脸**：人物身份参考由陪伴插件提供，食物图只承担场景角色，不会抢走角色的脸。
- **四种发送方式都行**：先说后说、分开发、一条发、引用发（见[快速开始](#快速开始)）。
- **一次投喂只有一条回复**：会自动压制它对食物照片的独立点评与即时表情，避免刷屏。
- **两套触发通道**：斜杠命令 `/投喂` 与自然语言「投喂」，可单独开关。
- **安全硬闸**：过小的图片、含酒精等关键词的投喂，会在调用模型之前就被拦下。
- **可只给本插件换生图接口**：想让投喂换一个生图模型，不必改陪伴插件的全局配置。

## 前置依赖

> **必须先有陪伴插件才能使用。** 本插件不自己实现视觉、生图与人设，这些全部复用：

| 依赖 | 用途 | 说明 |
| --- | --- | --- |
| `astrbot_plugin_private_companion`（陪伴插件） | 人设、视觉理解、生图、图片落盘、状态注入 | **硬依赖**；装了但未启用时本插件会提示「桥不可用」 |
| 可用的视觉模型 | 识别食物 | 需支持图片理解；配置留空即用 AstrBot 当前默认模型 |
| 可用的生图后端 | 出图 | 在陪伴插件侧配置（在线图片 API / ComfyUI 等），本插件不重复配置 |

未安装陪伴插件时本插件**不会工作**（设计如此，不做降级）。

## 安装

**方式一：插件市场**（推荐）
在 AstrBot 的插件管理中搜索本插件并安装。

**方式二：手动安装**
把插件目录放到 AstrBot 的 `data/plugins/` 下，**目录名保持 `astrbot_plugin_bot_treat`**：

```text
data/plugins/
└── astrbot_plugin_bot_treat/
    ├── main.py
    ├── metadata.yaml
    ├── _conf_schema.json
    ├── logo.png
    └── ...
```

随后重载插件或重启 AstrBot。**无需安装任何第三方依赖**（`requirements.txt` 为空）。

## 快速开始

在 Bot 的**私聊**里发一张食物照片，然后发送：

```text
投喂
```

或直接使用斜杠命令：

```text
/投喂
```

群聊中需要 @ 机器人或带唤醒前缀（这是 AstrBot 框架的唤醒规则，插件无法绕开）。

### 四种发送方式都能识别

| 你的操作 | 结果 |
| --- | --- |
| 照片 →「投喂」 | ✅ 一条回复（进食图） |
| 「投喂」→ 照片 | ✅ 一条回复 |
| 照片和「投喂」放在**同一条消息** | ✅ 一条回复 |
| **引用**那张照片再发「投喂」 | ✅ 一条回复 |

触发词（句首匹配，且**必须同时带图**）：`投喂`、`喂食`、`喂饭`、`给你吃`、`请你吃`、`尝尝这个`、`吃这个`。

只带图不说触发词（例如「喂你吃饭了吗」这类闲聊）**不会被误触发**。

## 配置项

在 AstrBot 的插件配置页中调整。

### 功能开关

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enable_feed` | `true` | 总开关 |
| `enable_private` | `true` | 允许私聊投喂 |
| `enable_group` | `true` | 允许群聊投喂（群聊需 @ 或唤醒） |
| `enable_natural_language` | `true` | 自然语言通道。**若私聊里「投喂」被别的插件吃掉**，关掉它并只用 `/投喂` |
| `dry_run` | `false` | 演练模式：照常识别与决策但**不出图**，只回一条调试文本（用于验证链路而不打扰聊天） |

### 进食规则

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `daily_limit` | `5` | 每日被「吃下」的次数上限，超出后拒绝 |
| `cooldown_sec` | `30` | 两次投喂的最小间隔 |
| `satiety_threshold` | `3` | 今日已吃下这么多次后**必定**拒绝 |
| `extra_block_keywords` | `[]` | 额外的拒绝关键词（默认已内置酒精等） |
| `min_image_bytes` | `6144` | 小于此大小的图片直接拦下（防表情包误投） |

### 生图

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `gen_kind` | `selfie` | 进食照片的生图类型：`selfie` = 角色自拍（保脸，推荐）/ `edit` = 以食物图为基础改图 / `text2img` = 不含角色的纯场景 |
| `use_food_as_ref` | `true` | 让食物照片作为参考图参与生成。关掉后改为**只用文字描述还原食物**（不传第二张参考图） |
| `persona_reference_image_path` | 空 | **角色身份参考图**，填本地绝对路径或图片 URL。留空 = 自动使用陪伴插件配置的人物参考图。若图片不在陪伴插件的数据目录内，本插件会**自动复制一份过去**（对方有路径白名单校验），所以填任意本地路径都能用 |
| `photo_timeout_sec` | `240` | 单次生图超时。带参考图的在线生图常需 1–3 分钟，**不要调小**，否则会在提交之后被杀掉 |
| `photo_api_base_url` | 空 | **可选**：仅投喂时使用的生图接口地址 |
| `photo_api_key` | 空 | 配合上一项 |
| `photo_api_model` | 空 | 配合上一项，如 `gpt-image-2.5` |
| `photo_api_size` | 空 | 配合上一项，如 `1024x1024` |
| `photo_api_override_sec` | `15` | 接口覆盖的保持秒数 |

> `photo_api_*` **全部留空 = 完全沿用陪伴插件的生图配置**。填写后只在投喂这一次临时切换，出图后自动还原，不改配置文件。

### 识别与容错

这几个键决定了「照片和文字怎么配对」，调错最容易出问题，所以写详细一点：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `vision_provider_id` | 空 | 食物识别用的视觉模型 provider id。**留空 = 用 AstrBot 当前默认模型**，推荐留空；该模型必须支持图片理解 |
| `vision_timeout_sec` | `30` | 单次视觉识别超时 |
| `llm_timeout_sec` | `45` | 进食决策（文本模型）超时 |
| `image_lookback_sec` | `120` | **回看窗口**：照片与文字分成两条消息发送时，允许往前找这么久内收到的图片。设为 `0` 则关闭回看（此时必须先发图再发触发词，且两条消息要挨得足够近） |
| `photo_hold_sec` | `6` | **照片挂起**：收到只带图、没有触发词的消息时，先挂起这么久等紧随其后的「投喂」。等到就接管该消息（压制对方插件对照片的独立点评）；等不到就完全不干预。副作用：**普通照片的回复会晚这么多秒**。设为 `0` 关闭 |
| `feed_wait_photo_sec` | `8` | **投喂后等图**：说了「投喂」但还没看到图时，静默等待这么久。期间照片到达即直接出图；等不到才提示「要带图」（斜杠命令）或完全不干预（自然语言）。设为 `0` 关闭 |
| `feed_watch_sec` | `150` | **回复抑制窗口**：投喂回合内该会话只放行本插件发出的进食图，其余出站消息（对方对照片的点评、即时表情）会被丢弃，以保证一次投喂只有一条回复。本插件发出进食图后窗口会自动收窄为 +20 秒。设为 `0` 关闭（可能出现多条回复） |

### 其他

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enable_memory_writeback` | `true` | 把这次投喂按陪伴插件的记忆格式写回（它会「记得」被投喂过） |

## 工作原理（简述）

```text
你发食物照片
   │
   ├─ 本插件事先把图片落盘（不依赖对方流程的时序）
   └─ 挂起最多 6 秒，等紧随其后的「投喂」
          │
          ├─ 等到了 → 接管这条事件，压制它对照片的独立点评
          └─ 没等到 → 完全不干预，照片按普通消息正常处理
   │
   ▼
安全硬闸（图片大小 / 关键词）→ 视觉识别食物 → 结合状态做吃 / 不吃决策
   │
   ├─ 不吃 → 回一句符合人设的拒绝
   └─ 吃   → 生图（人物身份参考 + 你的食物照作场景参考）→ 发图
```

几个值得一提的实现取舍：

- **先落盘再挂起**：一旦接管某条照片消息，对方插件就不会再处理它，所以图片必须由本插件自己先存好。
- **两张参考图分角色**：生图时传入两张参考图，并在提示词里用序数说明区分职责（第 1 张承担人物身份、第 2 张承担食物与场景），避免食物照被当成身份参考而「抢脸」。
- **身份参考图从哪来**：优先用配置项 `persona_reference_image_path`；留空则自动向陪伴插件要它配置的人物参考图。**注意**：对方对参考图有路径白名单（必须位于它自己的数据目录内），所以本插件会把不在白名单内的图**自动复制进它的数据目录**再传 —— 填任意本地路径都能用。
- **生图超时单独一张表**：生图是重任务，绝不复用文本模型那几十秒的超时，否则会在提交之后被杀掉。
- **生图失败不谎报**：生成失败时只回一句中性的「没吃成」，绝不复用那句以「已经吃了」为前提的台词。
- **只注册一个入口**：框架会在唤醒检查阶段把唤醒前缀（默认 `/`）从消息文本上剥掉，因此 `/投喂` 与「投喂」在插件视角完全一样。若再额外注册一个命令 handler，同一条消息会被处理两次、重复生图 —— 所以只保留统一入口。

## 常见问题

**Q：Bot 一直回「投喂要带图哦」？**
A：说明它没拿到图。确认是**先发图、再发「投喂」**；图片与文字分两条发送时本插件有 120 秒回看窗口，正常能取到。仍失败请把日志里以 `bot_treat:` 开头的行发出来。

**Q：Bot 说「太饱了」不吃？**
A：这是设计行为。`satiety_threshold`（默认 3）表示「今日已吃下这么多次就必定拒绝」；距上次投喂太近也会被拒。想连续测试可调高阈值或调大 `daily_limit`。

**Q：为什么不出图 / 提示「没吃成」？**
A：依次检查：① 陪伴插件的生图后端是否可用（去陪伴插件侧单独测一次生图）；② `photo_timeout_sec` 是否被调得太小；③ 日志里决策是否为 `decision=eat`。生图耗时 1–3 分钟属正常，请耐心等待。

**Q：会不会影响它别的功能？**
A：本插件只在「带图的触发词」上介入，其他消息一律不插手。若确实有影响，把 `enable_feed` 关掉即可完全停用。

**Q：会影响它**其他**的生图吗（自拍、说说配图）？**
A：不会。只给投喂换生图接口时，`photo_api_*` 只在投喂这一次临时生效并在 15 秒后还原，**不改配置文件**。代价是这 15 秒内如果它恰好在生图，那一次可能串用你填的接口 —— 概率低但无法 100% 隔离，介意就别填。

**Q：生成出来的角色不像它本人 / 脸不对？**
A：说明生图时没拿到角色身份参考图。推荐直接用配置项 `persona_reference_image_path` **显式指定**一张角色图（本地绝对路径或图片 URL）——这是最可靠的方式，尤其适合陪伴插件那边还没配置人物参考图的全新安装。

**Q：支持哪些平台？**
A：目前**在 OneBot v11（aiocqhttp / NapCat 等）实测可用**。其他适配器理论可用，但本地图片落盘需要你自行验证。

## 已知限制

- **强依赖陪伴插件的内部能力**。本插件通过陪伴插件的运行实例调用其生图 / 视觉 / 人设能力，**陪伴插件大版本升级后可能需要同步适配**。
- **投喂回合内会短暂压制它的回复**：为保证「一次投喂只有一条回复」，`feed_watch_sec`（默认 150 秒，本插件发出进食图后会自动收窄）内该会话的其它出站消息会被丢弃。嫌长可调小。
- **生图耗时较长**：带参考图的在线生图通常 1–3 分钟，属后端限制而非插件问题。
- **普通照片的回复会晚 `photo_hold_sec` 秒**（默认 6 秒）：这是「等一句可能到来的投喂」的代价；超时后它的正常流程照走。

## 目录结构

```text
astrbot_plugin_bot_treat/
├── main.py               # 插件入口：事件处理、照片挂起、出站结果闸门
├── decision.py           # 配置解析、状态机（冷却 / 饱腹 / 跨天）、吃不吃决策
├── prompts.py            # 识别提示词、决策提示词、生图提示词、兜底文案
├── companion_bridge.py   # 与陪伴插件的能力桥（实例发现、视觉、生图、参考图、图片落盘）
├── _conf_schema.json     # 插件配置项定义
├── metadata.yaml         # 插件元数据
└── logo.png              # 插件图标
```
